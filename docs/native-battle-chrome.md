# Native battle chrome and particle observations

Battle panel wrappers enter the existing native panel pass. Repeated base
calls paint once, including translucent artwork. Window queries use imported
cartridge templates and the actual native surface width. Healthbox captures
validate the current battle and battler, use native geometry, and apply owned
offsets inside a restored graphics scope. Native shown ailment state stays
separate from queued logical status changes.

Trainer images and picture offsets resolve from native imported records.
Additional genuine window templates and the native trainer portrait index
are retained by new imports. Existing imports retain their available records;
unavailable windows and artwork are reported rather than invented.

The particle observation module projects actual native event poses at the
current clip/frame. It cannot advance a clock or create combat particles.
Reversible position, scale, reflection, visibility and custom drawing changes
compose around the same native event painter, including OAM-composited draws.
The ordinary native path avoids these observations until a consumer asks for
the pool. Retired events and unloaded owners leave no visible source rows.
This is not a complete external animation VM or managed-sprite API.

ROM-free tests cover all five GBA editions. The real Metal/OpenGL host uses
asymmetric synthetic sprites and panels, independent pixel remapping, native
text shaders, multiple logical widths and healthbox offsets. It does not load
the original package or demonstrate complete gameplay.

The unchanged local package has progressed beyond the previously missing
battle chrome, healthbox, trainer-picture and picture-coordinate imports.
Additional battle/UI contracts remain. The complete battle presentation
protocol is not advertised by this change. No private runtime or cartridge
assets are included.
