# Native selection presentation

The confirmed unchanged-mod actor capture in `43b5eb8d59-firered` stops at missing `Ui.targetHidden`. Actor capture also reads selection displacement and a white palette coefficient. These queries now observe the admitted native battle rather than creating a UI clock.

The native GBA presentation update records the actual choosing actor and target. Existing native ticks own target changes, eight-frame blink periods and selection bounce origins. Queries never start or advance a controller. Native battler painting and native healthbox placement use the same controller as source UI consumers. Other engine generations do not enter this new update path. The existing native transform-white state supplies the bounded 0..16 coefficient; this does not implement a separate preview/menu state machine.

Integer selection motion uses imported `gen3BattleAnimSine`, starts at128 for healthboxes and192 for mons, and uses signed fixed-point floor division. Ordinary selection delta is7; target healthbox delta is15. Missing imported sine values yield no verified displacement. No floating sine substitute is introduced. Reference: [pret/pokefirered battle_main.c](https://github.com/pret/pokefirered/blob/ce6406d8c2eaf46d543c8a2606de0c3cb1951982/src/battle_main.c) (`DoBounceEffect`, `SpriteCB_BounceEffect`, `SpriteCB_ShowAsMoveTarget`, `SpriteCB_BlinkVisible`) and [battle_controller_player.c](https://github.com/pret/pokefirered/blob/ce6406d8c2eaf46d543c8a2606de0c3cb1951982/src/battle_controller_player.c) (`HandleInputChooseAction`, `HandleInputChooseTarget`). This reference is not an all-edition cartridge parity claim.

The new fixture covers five admitted GBA battles, query purity, signed integer motion, continuity through move selection, real additional battlers in doubles, target changes, eight-frame boundaries, side bindings, white coefficients and replacement/retirement.
